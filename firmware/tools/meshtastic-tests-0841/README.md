# Meshtastic 0.8.41 verification

`protocol.cpp` compiles the allocation-free production protobuf decoder. Independent golden vectors cover text, nodes, optional GPS coordinates (including 0,0), positional timestamps, malformed wire types, UTF-8 boundaries, canaries and 100,000 deterministic random packets. Wire fields were checked against the official Meshtastic `mesh.proto` (`Position`, `NodeInfo`, `MeshPacket`), retrieved 2026-10-24 from https://raw.githubusercontent.com/meshtastic/protobufs/master/meshtastic/mesh.proto .

`codec-store.cpp` compiles the unchanged namespace of `Tab5MeshStore.cpp` and the production binary codec. A fake File/Preferences boundary exercises maximum-size history, ring chronology, all truncations, CRC and CRC-valid structural mutations, malformed coordinates, NVS preferences, short writes, rename failure, corruption fallback, PSRAM failure and unmounted SD. No hardware filesystem or power interruption is claimed.

`backend-ui.cpp` compiles the unchanged namespace of `Tab5Meshtastic.cpp`, real LVGL 9.6 and the production Focus/TextInput/UiStyle code. ESP/NimBLE entry points are simulated. It covers callback authentication, explicit PIN confirmation, fragmented reads, bounded peers/nodes/messages, stable controls, native/pin Enter handling, keyboard layouts, real dark palette, modal options, positions/map actions, unread state, known devices, retry/backoff/stop policy, stale command cancellation, asynchronous persistence dispatch/merge, nodes-only history, memory rejection, standalone options without radio startup, strict ready-state badge reporting and repeated cleanup. Nine screenshots are rendered, with application allocation/free counts checked. IO tasks are explicitly completed by the harness; successful BLE worker scheduling is not simulated.

```sh
python3 tools/meshtastic-tests-0841/run.py --lvgl /path/to/lvgl-9.6.0 --lvgl-build /path/to/host-lvgl --build /tmp/tab5-meshtastic-tests-0841
```

The LVGL directory must contain `liblvgl.a` and `lv_conf.h`. AddressSanitizer and UndefinedBehaviorSanitizer are enabled. LeakSanitizer is disabled because executor process inspection is unavailable. The runner hashes production and test sources and rejects a run if they change. Main integration, complete firmware linking and the top badge are validated by the release tests, not this isolated harness.

## Memory and persistence

The pinned ESP32-P4 SDK 3.3.9 uses ESP-IDF v5.5.4 and compiles NimBLE with `CONFIG_BT_NIMBLE_MEM_ALLOC_MODE_INTERNAL=1`, NVS persistence and a 5,120-byte host stack. Version 0.8.41 compiles the byte-identical official `bt_osi_mem.c` translation unit locally using its supported EXTERNAL mode for this reviewed configuration only. Its six C exports supply the SDK's allocator references; the final release link check verifies that the original archive member was not pulled in. Generic host allocations use `SPIRAM|8BIT`; explicit `*_internal` calls retain `INTERNAL|8BIT|DMA`. The Hosted transport archive does not reference these allocators. Other SDK configurations retain their native allocator. Source, license, caps and SDK provenance are recorded in `tools/verification/meshtastic-sdk-0841.json`.

`memory.cpp` links that actual C allocator with a simulated heap boundary and the production `Tab5ResourceManager`. It reproduces the prior 72 KiB free-memory profile failing after the 8 KiB worker is allocated, then verifies admission with separate 28 KiB internal / 44 KiB PSRAM budgets. The existing global 32 KiB internal and 512 KiB PSRAM safety margins stay unchanged. Tests distinguish total-memory and contiguous-block refusals, inspect allocation capabilities, exercise null frees and calloc failure, and run 200 caller-owned pool rollback cycles. They do not emulate every internal NimBLE startup path. In particular, the vendor's fatal malloc/NPL assertions are retained. These budgets remain admission estimates, **not measured board peaks**.

The runner also compiles an unrecognized-version fallback and verifies that it exports none of the six replacement functions. Backend tests cover host initialization/task-creation error cleanup and suppress automatic retry after a memory refusal. Successful BLE worker scheduling and hardware shutdown remain outside the simulated boundary.

The 36,236-byte bounded history model, context, UI scratch and persistence snapshots use PSRAM. IO/BLE task stacks, explicitly internal SDK allocations and Hosted transport allocations remain internal. Eight known radio addresses/options persist as a CRC-protected NVS blob; PINs are never stored by the application. NimBLE owns bonding in its configured NVS store. An authenticated bond is still required unless the user explicitly selected no-pairing mode. Authentication failure blocks retries, repeat-pairing is not silently accepted, and a map-display option cannot rearm rejected authentication.

History contains at most 128 communications/position records and 32 nodes. The on-disk snapshot is bounded to 48 KiB, with two alternating CRC-checked generations under `/System/mesh` plus one temporary file. Only the inactive generation is replaced, after write/flush/readback checks. Saves occur on dirty state with a five-second debounce; failed allocation/task admission also waits five seconds. A failed initial SD read never enables history writes: existing generations remain untouched, live data stays in memory, and reads retry after thirty seconds. Preferences can still persist to NVS; Bluetooth may start after the failed read. No scans or writes occur on idle ticks. Closing the foreground view keeps Bluetooth only when background listening is enabled. An explicit stop cancels pending text/PIN commands and prevents automatic restart until resumed.

Physical radio interoperability, ESP-Hosted/C6 coexistence, actual heap/stack high-water marks, sustained background reception, loss/reconnect behavior and `nimble_port_stop()` failure remain untested on hardware. The real GCC 14.2 ESP32-P4 compiler and restored SDK headers compile both production modules; that establishes target compatibility, not radio behavior.
