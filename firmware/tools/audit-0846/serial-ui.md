# Réglages série et état UI — 0.8.46

L'ancien bouton Appliquer appelait `configure`, avec 400 tentatives espacées de 5 ms sur la tâche graphique. Un worker empêché de traiter la demande pendant cette fenêtre provoquait un message d'échec, alors que la demande était encore présente et pouvait être appliquée ensuite. La simple substitution par `requestConfigure` n'aurait pas suffi : son mutex protège aussi l'installation du pilote et NVS, et pouvait attendre ces opérations.

La demande UI et l'observation de son résultat utilisent maintenant une prise de mutex sans attente. Le service de la boucle UI ne consulte le résultat que lorsqu'une demande UI est en cours. Il ne crée aucune tâche ni minuterie, ne rappelle pas LVGL depuis le worker et ne signale pas une réussite au moment de la mise en file. Le bouton d'annulation utilise aussi cette voie sans attente du mutex ; les API synchrones pour démarrage/terminal restent disponibles.

La relecture indépendante a trouvé un deuxième cas : lorsque le port n'était pas prêt, une écriture NVS échouait mais le retour à la même configuration rétablissait `ready`. L'ancien résultat `ready && current == requested` signalait alors une réussite erronée. Le résultat réel déjà détenu par le worker est désormais exposé dans Stats et vérifié par les deux chemins, synchrone et UI. Aucun paramètre n'est effacé en cas d'échec.

Les sources exactes de la 0.8.45 livrée et les sources actuelles ont été compilées sous ASan/UBSan avec des frontières UART/USB/NVS/FreeRTOS contrôlées. Dans la panne injectée, l'appel ancien attend 2 000 ms simulées puis annonce l'échec avant une réussite ultérieure ; le nouvel appel n'effectue aucune attente, observe le résultat ultérieur, distingue le refus NVS et préserve la configuration antérieure. Sont aussi couverts : mutex déjà détenu, lecture exclusive, envoi en cours, configuration inchangée, paramètres invalides, absence de notification de succès prématurée. Le test exécute le namespace de production et la fonction UI de complétion ; il ne simule pas un périphérique physique. LSan est indisponible dans l'environnement et désactivé explicitement. Les preuves sont `serial-async-0846.json` et `serial-target-0846.json`.

Dans le main, huit vidanges UART explicites superflues ont également été retirées du parcours normal d'ouverture Cartes. Les messages restent présents. Cela ne rend pas `Serial0.write` non bloquant et aucun gain en millisecondes n'est revendiqué. Le clic sur un onglet Média déjà actif ne reconstruit plus son catalogue ; le bouton Actualiser conserve son rôle.
